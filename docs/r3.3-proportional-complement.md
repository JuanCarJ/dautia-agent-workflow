# DautIA r3.3 — complemento proporcional

Este complemento hace explícitos cuatro límites del ciclo sin convertirlos en
una ejecución automática: el paquete mínimo que puede consultar Jev por etapa,
la reserva y reconciliación de una delegación, la frontera de evidencia de QA y
la evidencia de componentes cuando un objetivo cruza repositorios.

## Controles

- **Antes de delegar:** `workflow_dispatch` vuelve a validar el candidato,
  reserva una clave idempotente local y exige reconciliar una reserva previa
  cuyo resultado no se conozca. Una excepción posterior al spawn queda como
  `dispatch_outcome_unknown`; nunca se reintenta automáticamente.
- **Durante la delegación:** `workflow_delivery` acepta únicamente la pareja de
  hashes del paquete/candidato, un estado de objetivo explícito y una reserva ya
  iniciada. Una entrega vieja queda `stale`; una entrega posterior a pausa,
  cancelación, interrupción, fallo, bloqueo o finalización se conserva como
  `late_ignored`. Checks y pendientes acotados viajan en el recibo para que el
  principal actualice el objetivo sin tratar el recibo como aprobación.
- **Jev:** cada etapa recibe únicamente su proyección allow-listada. Si falta un
  mínimo, Jev se abstiene en esa etapa y el flujo local sigue siendo independiente.
  La consulta no otorga autoridad ni certifica finalización.
- **QA:** `qa-prepare` y `qa-write` crean un espacio opt-in de evidencia. El
  helper solo escribe bajo `evidence_root`; `native_enforcement_observed` queda
  en `false` hasta que el host pruebe su frontera real.
- **CI/CD:** `component_evidence` permite registrar SHA, repositorio, checks y
  dependencias de cada componente. En un contrato compartido exige la relación
  explícita solo a componentes marcados `dependent`; un componente `independent`
  no se bloquea por esa razón. En cierre, cada componente requerido bloqueado o
  sin checks impide el cierre; no inventa un despliegue ni sustituye la revisión.
- **Telemetría:** `objective-report` resume como máximo 30 objetivos observables
  del event stream, conserva unknowns y no vuelve a sumar tokens del colector.

## Límites de esta entrega

Las pruebas usan fixtures y transportes sintéticos. No prueban capacidad real de
Sol/Astra/Jev, un spawn nativo del escritorio, proveedor externo, producto,
servidor o despliegue. La instalación activa global tampoco se modifica; el
artefacto debe probarse en un `HOME` temporal después de integrar este PR.

# Mandatory orchestration contract

A material product, test, migration, or versioned-configuration implementation must
resolve a native implementation child before writing. The packet records the exact
`runtime.required_agent_type` returned by `dispatch-plan`; it must be an
`implementer__PROFILE`, `implementer_complex__PROFILE`, or
`systems_implementer__PROFILE`. The child runs with `fork_turns: "none"` and returns
an observed model/effort, child reference, terminal evidence, and completed state.

The principal may write directly only for a trivial delta or an explicit user
exception recorded in `runtime.direct_execution_exception` with `scope: trivial`,
`source_kind: user`, source references, and a reason. A missing or malformed target
blocks preflight for material implementation. A missing or mismatched receipt blocks
closeout. A generic analyst, reviewer, or explorer cannot satisfy the implementation
receipt.

Every product-code implementation still requires an independent reviewer on the
final candidate. Broad or redesigned visual work also requires a qualified
`ux_auditor__PROFILE` receipt plus baseline, viewport, responsive, accessibility, and
visible-content evidence. Read-only discovery and audit remain direct unless their
packet explicitly requests a child, so the rule does not create ceremony for reads.

# DautIA Workflow Evaluation

Compare actual acceptance, authority and total cost on the same contract. For an AGENTS.md, skill, routing or instruction audit, read [instruction audit](references/instruction-audit.md): recommend before changing; audit authority alone does not permit edits. An ordinary configuration review needs no runtime pilot unless execution is requested. Use the real Codex harness, never a Claude runner relabeled as Codex. Shared skills are the domain contract; vary model/effort only in controlled comparisons. A requested profile is not evidence of effective routing.

## Select the evaluation boundary

- **Small behavioral replay:** inspect `scripts/run_replay.py --help`. Its eight sanitized cases cover authority, evidence, UI lineage, provider preservation and routing. The runner uses installed Codex CLI/account, bounded duration, a read-only sandbox, and disabled MCP/plugins. It performs no provider operation, transaction or new user task and uses no production fixture. Run `--dry-run` to inspect scope; `--run` spends account usage. Keep cases and contract identical across profiles. For GPT-6 migration start with Sol medium/high, Luna high and Astra low; use Astra medium only for a concrete unresolved analytical question. Astra medium is the ceiling; max/ultra and higher Astra efforts are excluded, and Sol xhigh needs explicit authorization. Historical v11/v12 expectations are not the active GPT-6 oracle. Runtime headers, completed outcome and reported usage matter. This replay does not prove implementation performance or automatic skill discovery; check fresh-session discovery separately.

- **Versioned GPT-6 decision replay:** run `scripts/run_gpt6_pilot.py --repo <workflow-checkout> --output <private-output> --codex <compatible-client>` first without `--run`, then with `--run`. It freezes contract, cases, runner and grader dependency. Its isolated `CODEX_HOME` links temporarily to existing auth; normal/handled exit removes that link, while an interrupted host may need pilot-owned link cleanup. Calls are real; product/provider operations are excluded. Require runtime context, a completed response, acceptance and no tool calls for a pass. Preserve v1/v2 failures and rubric amendments; changed fixtures are not a controlled comparison. Use `--profiles` for a relevant uncertainty. Verify exact client support when CLI lags app availability. This runner does not prove native subagent dispatch; use a separate child pilot for generated definitions.

- **Bounded nested-role simulations:** run `scripts/run_workflow_simulations.py --dry-run --output <owner-only-scratch>` first, then `--run` when execution is authorized. Each sanitized case uses a fresh fixture and its absolute directory as the model process cwd, one real Codex CLI root, and grading of artifacts plus the child's archived `turn_context` and terminal event. Providers, plugins and network are disabled; multi-agent remains enabled. In dependent cases the downstream child emits the frozen contract receipt before editing. That shows observable acceptance, not decryption or bytewise comparison of encrypted spawn content. Positive cases force named roles and prove runtime resolution, not autonomous selection or relative model quality; the copy control needs no child. Read `references/workflow-simulation-cases.json` only to maintain fixtures or acceptance.

- **Natural-routing v12 suite:** use the same runner with `--suite v12` and `--workers 1`; parallel execution of this fixture-cwd mode is unvalidated. `--dry-run` freezes `control/frozen-plan-v12.json` with fixture, routing, artifact and effective-contract fingerprints; `--run` refuses drift. The model workspace is its sibling, not an OS read barrier. Observable access to the frozen plan or installed v12 catalog invalidates that case. Grade a unique terminal `SIM_RESULT` value per expected key with frozen exact/bounded rules; narrative mentions, contradictory duplicates and unsafe nonempty values fail. The runner scopes trust per case, keeps raw sessions owner-only, publishes sanitized results without messages/thread IDs, and removes only its scratch trust entries, including after exceptions. The catalog keeps 26 baseline cases plus nine versioned corrective/expanded cases for acceptance/test conflict, handoff, server, mobile and CI boundaries; counts describe coverage, not frequency. Prompts do not name roles. Read `references/workflow-v12-cases.json` only to maintain the suite. A hash-bound review receipt proves a separate reviewer emitted a favorable verdict for final bytes, not review depth or GitHub approval.

For full task evaluation, freeze baseline, fixtures, tools and acceptance. Compare resulting artifacts, escaped defects, corrections, user time and total usage including agents and handoffs; use replay/fakes for real-provider operations. Report unknown as unknown. Do not add reasoning tokens again to output or translate Codex usage into API dollars/subscription credits without billing attribution. Read `references/pilot-cases.json` only for fixture maintenance.

Keep the old personal skill-creator evaluation resources disabled but recoverable; use the system skill-creator for authoring, never legacy Claude scripts as Astra/Sol evidence. Collection is explicit and diagnostic; no recurring schedule without a cadence request.
